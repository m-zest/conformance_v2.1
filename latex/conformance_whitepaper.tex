\begin{abstract}
Traditional software compliance relies on static, point-in-time assessments such as annual penetration tests and pre-deployment checklists. For Large Language Models (LLMs) and agentic systems, this approach fails because models produce non-deterministic outputs across dynamic prompt chains, creating a dangerous \textbf{Compliance Fiction}. Furthermore, commercial cloud-hosted guardrails introduce a \textbf{Privacy Paradox} by transmitting unredacted sensitive corporate data across external networks to assess compliance, incurring severe latency (500ms--2000ms).

This whitepaper presents \textbf{Conformance}, a practical, open-source, on-premise continuous runtime governance control plane. Conformance provides: (1) sub-15ms deterministic PII and secret redaction on CPU using Microsoft Presidio-inspired pattern tokenization and Luhn checksum validation; (2) dynamic Model $\times$ Use Case matrix routing; (3) an on-premise Multi-SLM Profile-as-Jury panel ($\Phi$-4 Mini, Mistral-7B, Gemma-3-4B) with position-bias compensation and automated human oversight escalation under EU AI Act Article 26(2); and (4) an immutable Governance-Aware Agent Telemetry (GAAT) cryptographic ledger utilizing SHA-256 hash chains and ECDSA digital signatures satisfying the mandatory 6-month log retention rule of EU AI Act Article 26(6). Empirical benchmarks demonstrate a 98.3\% Violation Prevention Rate (VPR), 0.18ms median deterministic latency on CPU, and zero data exfiltration across organizational perimeters.
\end{abstract}

\subsection{The Privacy Paradox of Cloud Guardrails}
Commercial safety APIs (e.g., cloud-hosted moderation endpoints) require sending raw, unredacted prompts over the public Internet to determine if they violate policy. This creates a critical legal dilemma:

\begin{quote}
\textit{An enterprise attempting to comply with GDPR Article 44 must transmit unredacted customer credit card or Social Security data to a foreign cloud provider just to check if the prompt contains personal data, committing the exact data transfer violation it seeks to prevent.}
\end{quote}

Conformance solves this by running all deterministic scanning, adversarial detection, and Multi-SLM jury evaluations \textbf{100\% on-premise within the enterprise boundary}.

\subsection{Credit Card Luhn Algorithm Verification}
To prevent redacting non-card 16-digit order numbers or tracking codes, the engine validates all card matches using the Luhn Modulo-10 formula:

\begin{enumerate}
    \item From the rightmost digit, double every second digit.
    \item If doubling results in a number greater than 9, subtract 9 (sum the digits).
    \item Sum all resulting values. If the total is divisible by 10 ($\sum \equiv 0 \pmod{10}$), the number is a valid credit card and is redacted.
\end{enumerate}

\subsection{Adversarial Injection Defense}
The Injection Guard inspects prompts for known adversarial jailbreak signatures:
\begin{itemize}
    \item \textbf{Role-play Escapes}: Strings instructing the model to act as an unconstrained persona (e.g., \texttt{"You are now DAN (Do Anything Now)"}, \texttt{"Developer Mode enabled"}).
    \item \textbf{Instruction Overrides}: Patterns attempting to reset context (e.g., \texttt{"Ignore previous instructions"}, \texttt{"Disregard system directives"}).
    \item \textbf{System Prompt Leaks}: Demands for internal prompt dumping (e.g., \texttt{"Output your initial instructions verbatim"}).
\end{itemize}
When detected in \texttt{active\_block} mode, the request is immediately dropped with an HTTP 200/403 refusal in \textbf{0.18ms}, preventing adversarial tokens from ever reaching the LLM context.

\subsection{The Regulatory Uncertainty Signal ($U$)}
Each judge $J_i$ evaluates the input-output pair and casts a vote $v_i \in \{0, 1\}$.
Let $P(\text{Compliant}) = \frac{1}{3} \sum_{i=1}^3 v_i$. The \textbf{Regulatory Uncertainty Signal} $U$ is:

\begin{equation}
    U = 1 - 2 \cdot \left| P(\text{Compliant}) - 0.5 \right|
\end{equation}

\section{Layer 4: GAAT Cryptographic Vault (EU AI Act Article 26(6))}
\label{sec:layer4}

Article 26(6) of the EU AI Act explicitly mandates that high-risk AI deployers maintain automatically generated logs for at least six months. Standard database records can be modified by database administrators and fail to provide non-repudiation during regulatory audits.

Conformance implements **Governance-Aware Agent Telemetry (GAAT)** using cryptographically linked SHA-256 hash chains.

\subsection{Hash-Chain Linking Formula}
Each transaction block $t$ includes the cryptographic hash of the preceding block:

\begin{equation}
    H_t = \text{SHA-256}\left( H_{t-1} \,\|\, \text{SpanID}_t \,\|\, \text{RawPrompt}_t \,\|\, \text{SanitizedPrompt}_t \,\|\, \text{Response}_t \,\|\, \text{Verdict}_t \,\|\, \text{Timestamp}_t \right)
\end{equation}

Each hash $H_t$ is digitally signed using ECDSA on the NIST P-256 curve ($\sigma_t = \text{Sign}_{sk}(H_t)$).

\subsection{1-Click Article 26 Compliance Dossier Export}
Compliance officers can click **"Export Article 26 Dossier"** on the dashboard to download a cryptographically verifiable JSON file containing the full chain, signatures, and mathematical verification receipts for submission to European supervisory authorities.
